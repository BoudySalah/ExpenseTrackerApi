# ExpenseTrackerApi

Expense Tracker API is a .NET 10 ASP.NET Core REST API for tracking personal expenses, viewing summaries, and managing authenticated users with ASP.NET Core Identity.

## Features

- User registration and authentication using ASP.NET Core Identity endpoints
- Secure JWT-based bearer authentication
- Expense creation, listing, and deletion
- Spending summary by period or custom date range
- Demo data seeding for testing and UI development
- Swagger/OpenAPI documentation with authentication support

## Tech Stack

- ASP.NET Core 10
- Entity Framework Core
- SQL Server provider (optional real DB)
- In-memory database fallback for local development
- Swagger / Swashbuckle

## Getting Started

### Prerequisites

- .NET SDK 10.0 or later
- A terminal such as PowerShell, bash, or zsh

### Run the API

```bash
dotnet restore
dotnet run
```

The app runs by default with an in-memory database for local development, so it works without a configured SQL Server instance.

Open Swagger UI here:

- http://localhost:5110/swagger
- https://localhost:7053/swagger

## Default Configuration

The app uses the in-memory database by default:

```json
"UseInMemoryDatabase": true
```

If you want to use SQL Server instead, set `UseInMemoryDatabase` to `false` and provide a valid `DefaultConnection` connection string.

## Authentication

This API uses ASP.NET Core Identity API endpoints for authentication.

Common auth routes are generated by the framework, including:

- `POST /register`
- `POST /login`
- `POST /refresh`
- `POST /logout`

After logging in, include the returned JWT in the Authorization header:

```http
Authorization: Bearer <token>
```

## API Endpoints

### Auth

#### `POST /register`
Registers a new user.

Request body:

```json
{
  "email": "user@example.com",
  "password": "Password123!"
}
```

#### `POST /login`
Authenticates a user and returns a token.

Request body:

```json
{
  "email": "user@example.com",
  "password": "Password123!"
}
```

#### `POST /refresh`
Refreshes an expired or near-expiry JWT token.

### Expenses

#### `POST /expenses`
Creates a new expense for the authenticated user.

Headers:

```http
Authorization: Bearer <token>
```

Request body:

```json
{
  "amount": 250.50,
  "currency": "EGP",
  "category": "food",
  "note": "Lunch meeting",
  "date": "2026-11-07T12:00:00Z"
}
```

Response:

```json
{
  "id": "b9d2d5d1-3db9-4d76-b4dd-b4d2264b0df9",
  "amount": 250.5,
  "currency": "EGP",
  "category": "food",
  "note": "Lunch meeting",
  "date": "2026-11-07T12:00:00Z"
}
```

#### `GET /expenses`
Returns all expenses for the current user.

Query parameters:

- `from` (optional): start date
- `to` (optional): end date

Example:

```http
GET /expenses?from=2026-11-01T00:00:00Z&to=2026-11-30T23:59:59Z
```

#### `DELETE /expenses/{id}`
Deletes one expense belonging to the authenticated user.

### Summary

#### `GET /summary`
Returns a summary of expenses for the authenticated user.

Query parameters:

- `period` (optional): `today`, `week`, `month`
- `days` (optional): custom number of days
- `topCategories` (optional): number of categories in the result

Examples:

```http
GET /summary?period=month
GET /summary?days=7&topCategories=5
```

Sample response:

```json
{
  "period": "month",
  "days": null,
  "total": 14350.25,
  "currency": "EGP",
  "byCategory": [
    {
      "category": "food",
      "total": 4800.00
    },
    {
      "category": "transport",
      "total": 3200.25
    }
  ]
}
```

### Demo Setup

#### `POST /seed-demo`
Clears any existing demo expenses for the current user and seeds realistic sample transactions.

Headers:

```http
Authorization: Bearer <token>
```

## Example Workflow

1. Register a new user using `POST /register`.
2. Log in with `POST /login`.
3. Copy the JWT token from the response.
4. Add it to the `Authorization` header as `Bearer <token>`.
5. Create expenses using `POST /expenses`.
6. View totals with `GET /summary`.

## Notes

- Valid expense categories are: `food`, `transport`, `shopping`, `bills`, `entertainment`, `other`.
- Invalid categories are automatically normalized to `other`.
- Amounts must be greater than zero.
- Dates are stored in UTC.
